# 口播爆文生成器

输入一个留学生求职相关的话题或事件，从知识库和原文库取材，产出爆款口播稿。

## Mode 1: 创作

用户发一段描述（话题/活动/政策/招聘会），产出 2-3 版口播稿。

### Step 1: 读入
读取用户输入。输入可能是：
- 一句话话题（"留学生秋招 timeline"）
- 一段招聘会信息（"深圳 7 月 28 日海归专场，50+企业"）
- 一个具体问题（"OT 怎么刷"）

如果输入过于模糊（只有两三个词），追问一句：有什么具体信息想强调的吗？

### Step 2: 翻原文库
浏览 `library/`，根据当前主题匹配最相关的分类文件，从中找 2-3 篇相似爆文参考：

| 主题类型 | 文件 | 骨架 |
|----------|------|------|
| 招聘会/双选会/人才活动 | `library/招聘会活动.md` | B |
| 单企业/单组织直招（如福耀、字节、联合国） | `library/单企业直招.md` | B2 |
| 红利列举/赛道/通道/政策 | `library/赛道红利.md` | A1 |
| 认知纠错/行业深挖/误区 | `library/认知打破.md` | A2 |
| 时间线/简历/校招/家长监督 | `library/实操攻略.md` | A1/A2 |
| 官方平台/国际组织/渠道 | `library/平台工具.md` | A1 |

**只读匹配的那个文件**，不要扫全库。关注它们的：
- 钩子怎么起
- 节奏怎么走
- CTA 关键词怎么设

### Step 3: 加载知识
读取以下文件（必须全部读完）：
- `docs/structure-templates.md` — 钩子/骨架/CTA/人称规则/写作规范/企业轮换池
- `docs/jargon-lexicon.md` — 10 类黑话词库
- `docs/emotional-protocol.md` — 情绪数值控制协议
- `docs/domain-knowledge.md` — 核对：招聘时间线是否匹配当前月份、留服认证/档案/应届生身份等基础概念是否正确

### Step 4: 实时搜索
口播稿中涉及以下内容的，必须实时搜索确认：
- 具体企业当前是否在招聘、是否有海外/国际业务（每次换一批企业，不连用同一组。搜不到确切信息的用概括表述）
- 招聘会/活动的时间、地点、报名方式
- 政府平台名称和网址是否正确
- 政策条款的具体名称和金额

**禁止编造。** 搜不到确切信息的，用概括性表述代替（如"头部大厂"而非具体企业名）。企业名从 `structure-templates.md` 第六章轮换池中取，每次搜索验证后使用。**先从 `.last-used-enterprises` 读上次用过的企业，此次避开。** 创作完成后，将此次使用的企业名追加写入 `.last-used-enterprises`（保留最近 3 次记录，旧的覆盖掉）。

### Step 5: 创作
按以下流程产出 2-3 版：

1. **选钩子**：从 5 种钩子中选合适的，用对应句式模板 + 可选词库组合。每版用不同钩子类型
2. **选骨架**：通用列举（A1）/ 通用说教（A2）/ 招聘会（B）/ 单企业直招（B2），匹配主题。**用户可显式指定骨架**（如"用B""走A1""走A2说教式""五段式别加分析"），指定后锁定骨架，禁止自行切换。招聘会类必须用B，五段干净切开，不得滑入A2的分析展开节奏
3. **定情绪曲线**：按 `emotional-protocol.md` 选对应曲线（V 型反转 / 阶梯上升 / 脉冲式 / 正向权威 / 正向宣告）
4. **填内容**：结合用户输入的信息点 + 原文库借鉴的节奏 + 实时搜索的事实
5. **注入黑话**：每版至少 5-8 个赛道黑话词（对照 `jargon-lexicon.md`），必须有装逼高端词 + 与国内学生区分词。注意装逼有度，用家长能听懂的词，不炫互联网圈黑话
6. **定语气**：装逼、有噱头、精英感。居高临下分享信息差，像在泄露一个"普通人不知道"的秘密
7. **写 CTA**：评论区扣关键词 + 悠悠老师同步给您，必须明说发什么（岗位汇总/报名入口/补贴指南），不说"完整名单"
8. **加呼吸**：初稿写完后，逐句过一遍 `structure-templates.md` 第七章「口播呼吸与节奏规范」——塞气口词（啊呢嘛啦呀吧）、拆洋葱层（一句一信息点）、换临场词（扣/立马/全部打包好啦）、切短句（数字之间用句号不用逗号）

**人称规则**：自称"悠悠老师"（不用"我"）。目标受众是家长，留学生 = "孩子"。
**语气铁律**：始终对家长说话，用"你家孩子""别人家孩子""普通家长"制造圈层对比。
**区分铁律**：每版至少 2 处明确对比「海归 vs 国内应届生」，但每处不超过一句半，嵌在信息里不成段展开。
**呼吸铁律**：初稿不是终稿。写完必须做第二轮"加呼吸"——不改变信息，只改节奏。气口覆盖率：每两句至少一个虚词收尾。

### Step 6: 自检
逐项跑以下 16 条，不通过则修正：

**信息层（原 12 条）：**
1. 字数 190-300（以悠悠老师账号爆款原文为基准，主力区间 200-290）
2. 钩子必须是 5 种之一
3. 身体有料 — 每条信息可验证，无空洞废话；呼吸用设问（"怎么参加呢？XX"）允许，书面自问自答（"线下双选会的含金量在哪？"）禁止
4. 黑话密度 ≥ 5 个，含装逼高端词，且家长能听懂
5. 人称一致 — 自称悠悠老师；对家长说话时留学生=孩子
6. CTA 完整 — 有关键词引导 + 交付物承诺，用"扣"不用"敲"，用"同步给您"不用"发你"
7. 口语化 — 无公文腔、无破折号、无书面词（"参考往年""经持续XX天""大量明确标注"），单句 ≤ 25 字
8. 事实校验 — 涉及具体企业的已搜索确认在招/有海外业务；平台/政策已确认真实
9. 装逼感 — 语气有精英信息差的居高临下感，不是温和讲解
10. 区分国内生 — 至少 2 处对比，每处不超过一句半，不成段展开，用绝对否定不解释（"国内生呢？连投递资格都没有。"）
11. 企业轮换 — 此次用的企业名不与上次重复，搜索验证为真实有海外业务的企业
12. 比例轮换 — 不总用"90%"，换成九成/95%/绝大多数/没几个家长知道

**呼吸层（新增 4 条）：**
13. 气口覆盖率 — 每两句至少一个气口词（啊呢嘛啦呀吧）收尾
14. 洋葱完整度 — 每句只给一个信息点，无"压缩饼干句"（一句塞 4 个信息）
15. 临场词 — CTA 用了"扣"而非"敲"，"立马发给您"而非"发你"，"全部打包好啦"而非"打包好了"
16. 朗读测试 — 出声读一遍：不喘不过气、不卡壳、像在跟人唠嗑，不是念稿

### Step 7: 交付
输出 2-3 版口播稿，每版独立呈现。不贴风格标签。

### Step 8: 存飞书

稿子交付后，问用户"要存飞书吗？"如果用户说存，取用户选定的那一版（如果有多版），通过 Bash 写入飞书多维表格。

**执行步骤：**

1. 确认要存的稿子和原始输入话题
2. 将口播稿中的双引号转义为 `\"`，换行保留为 `\n`
3. 执行以下命令获取 token 并写入：

```bash
# 获取飞书 token
TOKEN=$(curl -s -X POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal \
  -H "Content-Type: application/json" \
  -d "{\"app_id\":\"$FEISHU_APP_ID\",\"app_secret\":\"$FEISHU_APP_SECRET\"}" | grep -o '"tenant_access_token":"[^"]*"' | cut -d'"' -f4)

# 写入记录（将实际稿子内容替换 SCRIPT_CONTENT 和 TOPIC_TEXT）
curl -s -X POST "https://open.feishu.cn/open-apis/bitable/v1/apps/$FEISHU_APP_TOKEN/tables/$FEISHU_TABLE_ID/records" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "fields": {
      "输入文本": "TOPIC_TEXT",
      "口播稿": "SCRIPT_CONTENT",
      "处理状态": "审核通过",
      "文案类型": "口播稿"
    }
  }'
```

4. 检查返回结果中 `"code":0` 表示成功
5. 告知用户："已存入飞书（状态=审核通过）。n8n 会在 2 小时内自动调用蝉镜生成数字人视频，视频链接会写回飞书表格。"

**写入失败处理：**
- 如果 curl 报错或返回 code 非 0，告诉用户具体错误信息
- 稿子保留在聊天里，用户可以重试或手动复制到飞书
- 常见的失败原因：环境变量未设置（`FEISHU_APP_ID`/`FEISHU_APP_SECRET` 为空）、表格权限不足

**字段说明：**
- `输入文本`：用户原始输入的话题/需求
- `口播稿`：用户选定的那一版稿子（不是全部 2-3 版）
- `处理状态`：固定写"审核通过"
- `文案类型`：固定写"口播稿"
- app_token：通过环境变量 `FEISHU_APP_TOKEN` 提供，不写入代码或 Skill
- table_id：通过环境变量 `FEISHU_TABLE_ID` 提供，不写入代码或 Skill

## Mode 2: 入库

用户发一篇新爆文原文，拆解后存入知识库。

### Step 1: 读入
用户发一篇爆文原文（通常在聊天里直接发文本）。

### Step 2: 拆解
标注以下信息：
- 钩子类型（对照 `structure-templates.md` 5 种）
- 结构骨架（A1 / A2 / B / B2）
- 每段对应的情绪曲线段位
- 新黑话（不在现有 `jargon-lexicon.md` 里的）
- CTA 变体
- 新的事实信息点（政策/平台/企业名）

### Step 3: 对比
将拆解结果与现有 3 个 docs 逐项对比：
- 钩子句式 → `structure-templates.md`
- 黑话词汇 → `jargon-lexicon.md`
- 情绪段位词汇 → `emotional-protocol.md`

列出所有"新增/变体/不同"的项。

### Step 4: 报告
向用户报告：

> "拆解完成。发现：
> - X 个新钩子变体：……
> - X 个新黑话：……
> - X 个新 CTA 变体：……
> 要更新 docs 吗？"

等待用户确认后再写入。

### Step 5: 更新
用户确认后：
1. 将新内容写入对应的 docs 文件
2. 将新爆文存入 `library/`（文件名用主题关键词命名，如 `深圳海归专场.md`）
